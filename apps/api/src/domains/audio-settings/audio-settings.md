# Audio settings

Audio settings belong to one account. `GET /v1/settings/audio` returns only `provider`, `workersAiAvailable`, `hasApiKey`, and `configured`. Providers are `workers_ai` (Cloudflare Workers AI Whisper, the default) and `openai` (the account's own key). A missing row defaults to `workers_ai`. `workersAiAvailable` is whether the Worker has a usable `AI` binding; `configured` is `workersAiAvailable` for `workers_ai` and `hasApiKey` for `openai`. Local Whisper no longer exists: migration `0002_workers_ai_transcription.sql` rebuilt the table's CHECK constraint and moved `local_whisper` rows to `workers_ai`, and the API rejects `local_whisper` with `400`.

`PATCH /v1/settings/audio` selects `workers_ai` or `openai`, optionally replaces `apiKey`, or explicitly removes it with `removeApiKey`. A key can stay saved while Workers AI is selected; it is then not used. Secrets never appear in responses. New key submissions require HTTPS or exact localhost/loopback origin; changing a provider or removing a stored key remains possible over trusted LAN HTTP. Mutation origin and expected-account guards still apply. No global OpenAI environment credential is used as a fallback for another account.

Keys are encrypted with AES-256-GCM, a fresh 96-bit nonce, and the owner ID as authenticated context. Only ciphertext is stored in the database. The master key is the 64-hex-character `ORDO_CREDENTIAL_KEY` secret (locally from `apps/api/.dev.vars`); without it credential storage reports unavailable and no key can be saved. Protect and back up this key separately from the database. Losing it requires users to add their provider keys again. No secrets belong in Git, client code, screenshots, request logs or exception messages. Saving settings is one upsert; leaving `apiKey` out keeps whatever key is stored at the moment of the write.

`POST /v1/settings/audio/test` tests the saved selection. Workers AI reports only whether the binding is available, because a test inference would spend the daily allowance. OpenAI tests the key with a fixed HTTPS `GET /v1/models` request, without audio or inference billing. This verifies credential acceptance, not transcription-model availability or sufficient balance. Concurrent tests for one owner are limited. Provider errors are sanitized.

The owning service resolves the account's chosen transcriber for each transcription and never substitutes one provider for the other: Workers AI selected without a binding returns `503 WORKERS_AI_UNAVAILABLE` even when an OpenAI key is saved, and OpenAI selected without a key returns `503 FEATURE_UNAVAILABLE`. The web client snapshots `X-Ordo-Audio-Provider` when recording starts; a missing snapshot or mismatch with saved settings returns `409 AUDIO_SETTINGS_CHANGED` before creating a provider, preventing an unnoticed provider change in another tab from sending a recording somewhere else. Another account cannot use that key, including by copying the ciphertext because the encryption authenticates owner identity. Settings changes never create recordings, files, or transcripts. Transcript text is returned temporarily; only an explicit user save creates a note.

## On Cloudflare

The master key is only the `ORDO_CREDENTIAL_KEY` Worker secret; there is no key file. Encryption uses AES-256-GCM through Web Crypto (`WebSecretCipher`), byte-compatible with ciphertext saved by the earlier Node implementation (a test decrypts a value it produced), so imported keys decrypt when the same master key is set.

The Worker's `AI` binding reaches Workers AI only on Cloudflare. `ORDO_WORKERS_AI` decides whether it is used: on when hosted, off when `ORDO_ENV=development` (where `wrangler dev --local` cannot reach Cloudflare), and `on` or `off` overrides either. With it off, `workersAiAvailable` is false.

`GET /v1/capabilities` reports `transcriptionProviders.workersAi` (the binding is usable) and `transcriptionProviders.openai` (credential storage is configured). It reports `recording` and `transcription` true when Workers AI is usable, or when the caller is signed in and its account has a saved OpenAI key; the endpoint stays public, and an absent or unknown session simply gets the runtime answer.
