# Captures

Authenticated recording storage and explicit transcription operate independently. `POST /v1/captures` accepts raw `audio/webm`, `audio/mp4`, `audio/ogg`, or `audio/wav` bytes (codec parameters allowed) up to 20 MiB. MIME and basic container headers are checked; this is not a full audio decoder. Empty, mismatched, or oversized input is rejected. An owner may retain up to 100 recordings or 200 MiB; no deletion UI is implemented yet.

`GET /v1/captures` returns owned metadata; `GET /v1/captures/:id` returns one recording; `/audio` serves owned bytes with explicit media type, nosniff and private no-store response. Files live in the configured private capture directory outside the webroot, under owner/recording UUID directories. Directories use owner-only permissions; audio and atomic metadata files use mode0600. No user filename is accepted. The data directory requires persistent storage and backup on deployment; this is a single-server implementation, not a shared object store.

`POST /v1/captures/:id/transcribe` explicitly sends that recording to the configured provider. With no provider it returns `503 FEATURE_UNAVAILABLE`; the UI must show Coming soon. `OPENAI_API_KEY` enables a fixed HTTPS OpenAI audio transcription adapter using `gpt-4o-mini-transcribe`, multipart file input and JSON text output. No API key or provider failure body reaches the client. No production provider request was performed during implementation; tests use fictional WAV fixtures and injected transports.

Processing is synchronous with a 60-second provider timeout. Metadata persists recorded/transcribing/transcribed/failed status and transcript; failures preserve original audio and support retries. Repeating a successful request returns the transcript without another provider call. Concurrent requests for the same recording are rejected within one process. Interrupted processing becomes retryable after a process restart. This is not a background worker or multi-replica job queue. Browser recording requires microphone permission and a secure HTTPS origin (localhost is a development exception); ordinary LAN HTTP cannot capture phone microphones.

Capability contracts isolate private storage and transcription. Domain service owns validation and state transitions, adapter owns filesystem/provider details, controller handles transport. All storage lookups use the authenticated owner and UUID, returning 404 for another owner's recording.
